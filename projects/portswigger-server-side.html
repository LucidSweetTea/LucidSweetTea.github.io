Project Overview

Completed the full 52-step PortSwigger Web Security Academy Server-side Vulnerabilities Apprentice learning path. The training combined technical instruction with hands-on web application security labs in an authorized environment.

The labs focused on identifying, validating, and understanding common server-side vulnerabilities while using Burp Suite to inspect and manipulate HTTP requests and responses.

Lab secrets, credentials, session tokens, and temporary training environment values are intentionally excluded from this portfolio.

Vulnerability Areas Completed

1. Path Traversal

Tested file path parameters for improper directory restrictions and demonstrated how unsafe path handling can expose files outside an application's intended storage directory.

2. Access Control

Tested vertical and horizontal privilege escalation scenarios, including insecure direct object references, exposed administrative functionality, and user-controlled authorization values.

3. Authentication Vulnerabilities

Analyzed authentication workflows for username enumeration, weak credential protections, two-factor authentication bypasses, and improper separation between authentication and authorization.

4. Server-Side Request Forgery

Used vulnerable server-side request functionality to identify unintended access to loopback and internal network services. Burp Intruder was used to test internal address ranges and Burp Repeater was used to validate discovered services.

5. File Upload Vulnerabilities

Tested insecure file upload controls and demonstrated the risks of trusting user-controlled MIME types. Modified multipart HTTP requests with Burp to validate Content-Type restriction weaknesses.

6. OS Command Injection

Identified unsafe user input reaching operating-system commands and validated command execution through controlled lab testing.

7. SQL Injection

Tested vulnerable SQL query parameters for hidden-data retrieval and authentication bypass. The exercises demonstrated the security impact of dynamically constructing SQL queries from untrusted user input.

Burp Suite Skills Demonstrated

  • Captured and reviewed HTTP requests using Proxy and HTTP History
  • Modified and replayed requests using Burp Repeater
  • Configured payload positions and automated testing with Intruder
  • Intercepted and modified live requests before forwarding them
  • Analyzed status codes, response lengths, headers, cookies, and bodies
  • Modified URL parameters, form data, cookies, and multipart requests
  • Compared application responses to identify behavioral differences

Security Concepts Reinforced

  • Server-side input validation
  • Parameterized SQL queries and prepared statements
  • Least privilege and authorization enforcement
  • Secure authentication and session handling
  • Internal network trust boundaries
  • Safe file upload validation and storage
  • Command execution risk and shell input handling
  • HTTP request and response analysis

Key Takeaways

  • Client-controlled values should never be trusted to make authorization or security decisions.
  • Small differences in HTTP responses can reveal authentication and authorization weaknesses.
  • Internal-only services still require authentication and strong access controls.
  • File extension and MIME-type checks alone are insufficient protection for uploaded files.
  • Parameterized queries and safe APIs are essential defenses against injection vulnerabilities.
  • Burp Suite provides an effective workflow for capturing, modifying, replaying, and comparing web application traffic.
